Environment variables (your server)

Never commit secrets. Use .env locally and Hetzner env / secrets file in prod.

# App
NODE_ENV=production
PUBLIC_APP_URL=https://yourdomain.com

# Database
DATABASE_URL=postgresql://...

# Redis / queue
REDIS_URL=redis://...

# Auth (Better Auth — names may match your config)
BETTER_AUTH_SECRET=<random 32+ bytes>
BETTER_AUTH_URL=https://yourdomain.com

# Encrypt Page tokens at rest
TOKEN_ENCRYPTION_KEY=<32-byte key>

# Meta (platform — one app for all tenants)
META_APP_ID=
META_APP_SECRET=
META_WEBHOOK_VERIFY_TOKEN=<you invent this string>

# LLM (POC: Groq only)
GROQ_API_KEY=

# Optional later
# DEEPSEEK_API_KEY=
# MOONSHOT_API_KEY=

Merchant Page tokens go in Postgres encrypted, not in env — one row per connected Page.

Groq setup (initial LLM)

  1. Sign up at console.groq.com → create API key.
  2. Pick a model with tool / JSON reliability for your agent (test Bengali + search_products calls).
  3. Set GROQ_API_KEY on worker (and Next if agent runs there).
  4. Monitor usage on Groq dashboard; upgrade only when free RPD/RPM blocks pilots.
Later Swap provider via a thin LLM client (DeepSeek/Kimi) without changing Meta or catalog code.

Webhook configuration

  1. Public HTTPS URL, e.g. https://yourdomain.com/api/webhooks/meta
  2. In Meta app → Messenger → Webhooks: paste URL + verify token → subscribe your test Page
  3. Subscribe fields (minimal POC): messages, optionally messaging_postbacks
  4. Implement GET handler: echo hub.challenge when verify token matches
  5. Implement POST: validate X-Hub-Signature-256 with App Secret → enqueue job → return 200 quickly
POST https://graph.facebook.com/v21.0/{PAGE-ID}/messages
  ?access_token={PAGE_ACCESS_TOKEN}
Body: recipient { id: PSID }, message { text: "..." }

Use current Graph API version from Meta docs. Standard replies: customer must message first; 24-hour messaging window after their last message.

Connect Facebook (merchant flow — no keys from them)

  1. Redirect to Facebook Login with your App ID + requested scopes
  2. Merchant selects Page and clicks Allow
  3. Exchange code server-side → short-lived user token → long-lived → Page access token
  4. Store page_id + encrypted page_access_token on tenant row
  5. Subscribe that Page to your app webhooks (Graph call with Page token)

Valid OAuth Redirect URIs in Meta app must include e.g. https://yourdomain.com/api/connect/facebook/callback (match your Better Auth / custom route).

Go-live checklist (before pilot merchant)

  • PUBLIC_APP_URL HTTPS works; Meta webhook shows green / receives test event
  • Webhook signature verification enabled (reject bad POSTs)
  • Test Page connected; inbound DM appears in Inbox
  • Human can send reply from dashboard → customer sees it in Messenger
  • ≥1 confirmed product + shop rules → AI toggle enabled
  • Groq key on worker; test tool call returns real price from DB
  • Page tokens encrypted; App Secret not in client bundle
  • Meta app Live + permissions approved (or pilot stays on test Page in Dev mode)
